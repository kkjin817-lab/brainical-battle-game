# 차곡 · 타이머 정지 미니게임

숫자 타일 게임의 첫 번째 미니게임을 독립적으로 테스트하는 웹 프로토타입입니다. **본게임에는 아직 삽입하지 않았고, 본게임 점수·저장 데이터·소스를 변경하지 않았습니다.** 사용자 테스트 후 스테이지 사이의 무작위 미니게임 흐름에 연결합니다.

## 실행

이 폴더에서 `node preview.cjs`를 실행하고 [타이머 정지](http://127.0.0.1:4176/)를 엽니다. Node 외에 설치할 패키지나 외부 네트워크 요청은 없습니다. IndexedDB와 Web Locks를 지원하는 최신 일반 Chrome/Edge에서 실행합니다.

테스트 점수 1,076점으로 시작합니다. 점수 선택 → 시작 → 3초 준비 → 정지 → 결과 → 다음 테스트를 반복할 수 있습니다. 점수가 부족하면 준비 화면의 **테스트 도구 → 테스트 점수 1,076점 추가**를 사용하세요. 기록은 유지하며 목표 시간도 바꾸지 않습니다.

마우스와 터치는 정지 버튼을 처음 누른 시각을 사용합니다. 키보드는 Space 또는 Enter입니다. 손을 떼는 시각이나 이후 생성되는 click 이벤트로 다시 정지하지 않습니다.

## PRD 해석과 이번 범위

사용자 요청의 ‘테스트 후 본게임에 삽입’을 우선하여 PRD의 본게임 즉시 연결 단계는 유보했습니다. 독립 테스트의 ‘다음 테스트’는 새 sourceRoundId와 miniGameId를 만드는 개발용 기능입니다. 기존 기회를 다시 쓰거나 같은 정지 기록으로 재지급하지 않습니다. 본게임의 실제 누적 점수를 가져오거나 추가 보상을 지급하지 않습니다.

보상은 사용자의 후속 수정 요청에 따라 v2에서 **3배 / 0.1초 이내 2배 / 0.2초 이내 1배 / 그 밖 0배**로 변경했습니다. 정확 판정은 기존 제안값 ±0.050초를 유지합니다. 원금을 포함한 배당이며, 다른 설정은 PRD의 테스트 기본값입니다.

| 항목 | 적용값 |
|---|---|
| 목표 | 1.000~10.000초 정수 중 균등 무작위, 준비 시 공개 |
| 정확 | 절대 오차 0~50ms, 원금 포함 3배 지급 |
| 성공 | 51~100ms, 원금 포함 2배 지급 |
| 반환 | 101~200ms, 원금 포함 1배 지급 |
| 실패 | 201ms 이상, 0배 |
| 자동 종료 | 목표+201ms, 성공 기록 없이 시간 초과 처리 |
| 준비 | 실제 3초 카운트다운, 이때 누른 정지는 무시 |
| 중단 | 시작 차감 이후 새로고침·탭 숨김·앱 전환 시 0배 정산 |
| 선택 | 100점 단위, 0점부터 선택, 최대 버튼은 금액만 변경 |
| 참여 | 건너뛰기 가능, 100점 미만이면 시작 불가 |

## 구현

- `engine.js`: 순수 배당 판정, BigInt 점수 계산, 이벤트 시각 정규화, 가짜 시계로 검사 가능한 TimerSession, 상태 전이.
- `storage.js`: IndexedDB 트랜잭션 내부에서 최신 기회·잔액을 다시 확인한 뒤 차감/지급/상태 변경을 원자적으로 저장.
- `app.js`: 준비, 타이머, 결과, 모바일 입력, 중단 복구, Web Locks의 단일 탭 소유권, 기록 내보내기.
- `style.css`, `index.html`: 기존 차곡과 연결되는 시각 디자인, 360px 대응, 시작/정지 버튼 같은 위치와 66px 높이.
- `test.cjs`: 순수 로직·경계값·가짜 시계·큰 정수 테스트.
- `tests.html`, `browser-tests.js`: 실제 브라우저 IndexedDB의 동시 거래, 저장 실패 롤백, 재시도, 잠금 테스트.

표시는 `performance.now()`를 프레임마다 읽어 갱신하고, 판정은 정규화한 입력 이벤트 시각에서 시작 시각을 뺀 뒤 밀리초를 내림합니다. 프레임 수를 더해 시간을 만들지 않습니다. 10초 목표의 늦은 정지 구간도 보장합니다.

자동 종료 시 이미 대기 중인 입력 이벤트를 받을 150ms의 처리 유예가 있습니다. 화면은 마감 시각에서 멈추며, 유예 중 들어온 **마감 이후 시각의 입력은 여전히 0배**입니다. 이는 성공 구간을 늘리는 기능이 아닙니다. 극단적인 브라우저 지연에 대해 무제한 복구를 보장하지는 않으며 실제 휴대폰에서 입력 지연을 추가 측정해야 합니다.

점수는 BigInt로 계산하고 십진 문자열로 저장합니다. 큰 점수도 정수 정밀도를 잃지 않습니다. 슬라이더는 항상 100의 배수를 선택하며 화살표 키는 100점씩, Home/End는 0/최대 금액으로 이동합니다. 큰 잔액의 전체 범위를 드래그할 때 픽셀 간격 때문에 여러 단계를 건너뛸 수 있으나 최대·±100 버튼은 정확한 정수로 동작합니다.

베팅 시작 저장에 실패하면 차감과 상태 변경이 함께 롤백되고 타이머를 시작하지 않습니다. 정지 저장이 실패하면 측정 결과와 eventId를 고정하고 저장만 1초 간격으로 재시도합니다. 그 전에 프로세스가 종료되면 마지막 영속 상태를 기준으로 중단 손실이 됩니다. 준비 화면의 목표와 확정된 결과는 재접속해도 유지됩니다.

## 검증 결과

`node test.cjs` — **17개 테스트 묶음 통과**. v2의 양쪽 50/51/100/101/200/201ms 경계값과 기존 기회의 규칙 갱신을 포함합니다.

새로고침하면 아직 시작하지 않은 기회는 목표·점수를 그대로 두고 v2 규칙으로 갱신합니다. 이미 시작했거나 정산된 베팅의 약정 배율은 변경하지 않으며, 화면의 배당표도 해당 기회의 규칙을 따릅니다.

[브라우저 저장소 테스트](http://127.0.0.1:4176/tests.html) — **6개 통과, 0개 실패**. 이 페이지는 매번 별도의 임시 DB를 만들고 자체 데이터만 정리합니다.

실제 UI에서 확인한 사항:

- 1,076점에서 최대 1,000점 선택 시 76점 유지.
- 미정지 시간 초과 0배, 허위 정지 기록 없음.
- 76점에서 베팅 시작 차단, 다음 테스트와 점수 보충 가능.
- 최초 포인터 입력으로 0.168초 정지 기록, 후속 click으로 다음 테스트에 넘어가지 않음.
- 100점 베팅 후 카운트다운 중 새로고침: 0배 중단 종료, 추가 차감 없음.
- 같은 저장소를 연 두 번째 실제 브라우저 탭은 베팅 화면 대신 연결 대기 표시.
- 360px 모바일 크기에서 준비·결과 화면 확인. 실제 휴대폰의 50ms 난이도 및 터치 체감 검증은 아직 수행하지 않았음.

QA 플레이는 `?test`를 붙인 주소의 별도 저장소를 사용합니다. 일반 플레이 주소에는 QA의 점수나 기록이 들어가지 않습니다.

## 테스트 후 연결 계획

1. 본게임 클리어 원자적 저장 안에서 수식 보상·다음 단계·미니게임 종류 추첨·기회·목표를 함께 저장합니다. 오판이나 중단에는 기회를 생성하지 않습니다.
2. `pendingMiniGameId`가 있으면 다음 수식 판보다 먼저 처리합니다. 정산 또는 건너뛰기 후에만 다음 단계로 갑니다.
3. `type: 'timer_stop'` 인터페이스로 이번 게임을 호출합니다. 종류가 추가되면 추첨은 기회 생성 시 한 번만 수행하고 재접속해도 유지합니다. 종류별 출현 가중치는 아직 정하지 않았습니다.
4. 20단계 뒤에도 미니게임을 먼저 마치고 최종 결과를 표시합니다.
5. 본게임의 현재 Number 점수와 미니게임의 문자열 BigInt 점수를 연결할 때 전체 점수 저장 스키마를 함께 마이그레이션합니다. 지금은 분리되어 있어 본게임의 저장값을 변경하지 않습니다.

PRD T01/T02/T20의 실제 본게임 통합 시나리오는 이 연결 단계에서 검증합니다. 이번 독립 테스트가 이를 완료한 것으로 간주하지 않습니다.

권장 관찰 항목: ±50ms 성공 빈도, 목표별 오차 분포, 전액 베팅 빈도, 총지급/총베팅, 중단 손실의 납득 여부. 테스트 도구에서 전체 이벤트·기회·결과 JSON을 내보낼 수 있습니다. 실제 현금 구매·환전·상품·세계 순위는 구현하지 않습니다.
