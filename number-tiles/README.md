# 차곡 · 숫자 타일 + 베팅 미니게임

수식 게임 한 판을 클리어할 때마다 등록된 미니게임 중 하나를 무작위로 제시합니다. 현재 타이머 정지 1개만 등록되어 있으므로 매번 타이머 정지가 나옵니다. 참여 여부와 베팅 금액은 플레이어가 선택합니다.

## 실행

이 폴더에서 `node preview.cjs` 실행 후 http://127.0.0.1:4175 를 엽니다. 추가 패키지는 필요하지 않습니다. Chrome/Edge의 IndexedDB와 Web Locks를 사용합니다.

이미 열려 있다면 새로고침합니다. 이전 버전 탭이 저장소 갱신을 막으면 안내에 따라 닫습니다. 기존 점수와 진행은 자동 이전됩니다. 독립 실험판 `../timer-stop/`의 테스트 점수는 본게임에 가져오지 않습니다.

### 스마트폰에서 같은 Wi-Fi로 테스트

PC의 IPv4 주소를 `ipconfig`로 확인합니다. PowerShell에서 `$env:HOST='PC의 Wi-Fi IPv4'; $env:PORT='4177'; node preview.cjs`로 실행하고 스마트폰 브라우저에서 `http://PC의-Wi-Fi-IPv4:4177/`을 엽니다. PC와 서버를 켜 둬야 합니다. 주소가 바뀌면 다시 확인합니다. PC와 휴대폰 점수는 각 브라우저에 별도로 저장됩니다.

로컬 Wi-Fi의 HTTP 접속에서는 Web Locks와 randomUUID가 없을 수 있습니다. 암호학적 랜덤 ID 대체 구현과 IndexedDB 기반 임대 잠금으로 대응합니다. 소유권은 12초 유효하고 4초마다 갱신합니다. 트랜잭션마다 소유자와 유효 기간을 다시 확인하므로, 연결이 끊긴 오래된 탭은 새 소유자가 이어받은 뒤 점수를 쓸 수 없습니다. localhost/HTTPS는 기존 Web Locks를 사용합니다. 방화벽/공유기 설정에 따른 실제 휴대폰 접속 가능 여부는 해당 기기에서 확인해야 합니다.

## 플레이 흐름

수식 정상 완료 또는 올바른 불가능 선언 → 수식 보상 정산 → 미니게임 도전 → 베팅 또는 건너뛰기 → 정산 → 다음 스테이지. 20단계도 미니게임을 마치거나 건너뛴 뒤 전체 결과를 표시합니다. 오판·미완료 중단에는 기회를 만들지 않습니다.

타이머 정지는 목표 1~10초를 공개하고 누적 보유 점수 중 100점 단위로 베팅합니다. 현재 배당은 원금 포함입니다.

| 절대 오차 | 지급 |
|---|---|
| 0~50ms | 3배 |
| 51~100ms | 2배 |
| 101~200ms | 1배, 원금 반환 |
| 201ms 이상 | 0배 |

베팅 시작 시 차감하고 3초 카운트다운 후 최초 터치 시각으로 정지합니다. 목표+201ms까지 미정지하면 시간 초과입니다. 시작 후 새로고침·탭 숨김·앱 전환은 추가 차감 없이 0배 종료합니다. 준비 화면에서 재접속하면 같은 종류·목표를 유지하고, 정산 화면 재접속은 중복 지급하지 않습니다.

## 확장 구조

- `minigames/registry.js`: 종류 등록, 가중 추첨, 기회 생성.
- `minigames/catalog.js`: 출현 목록과 가중치. 현재 timer_stop: 1.
- `minigames/host.js`: 공통 베팅 선택·결과·건너뛰기·저장 재시도·다음 단계 연결.
- `minigames/timer-stop-view.js`: 타이머 전용 카운트다운·입력·화면.
- `../timer-stop/engine.js`: 실험판과 공유하는 타이머·배당 계산기.
- `state.js`: 수식과 미니게임 진행, 공유 점수 차감/지급, 중복 이벤트 방지.
- `storage.js`: 최신 잔액·기회를 읽고 점수와 상태를 한 트랜잭션에 저장.

새 게임 추가 절차와 모듈 계약은 [MINIGAMES.md](MINIGAMES.md)를 참고하세요. 두 번째 가상 플러그인을 등록해 공통 정산을 그대로 사용하는 자동 테스트도 있습니다.

## 저장과 이전

수식 보상·다음 단계·미니게임 종류·목표를 한 번에 저장합니다. 재접속 때 추첨하지 않습니다. 미니게임을 처리해야 다음 단계로 갑니다. 공유 점수는 BigInt 계산 / 십진 문자열 저장으로 큰 점수도 정확하게 유지합니다.

v1→v2 이전은 기존 점수·단계·오판 감점·기록을 보존합니다. 원본은 같은 저장소의 progress-backup-v1 키에 보관합니다. 이전 버전의 수식 결과 화면에서 갱신하면 해당 판의 기회를 한 번 생성합니다. 이미 전체 완료된 기록에는 소급하지 않습니다.

Web Locks로 본게임은 한 탭만 활성화하며, 트랜잭션 안에서도 최신 잔액·기회·eventId를 검사합니다. 시작 저장 실패는 차감도 롤백합니다. 정지 저장 실패는 동일 결과/eventId로 재시도합니다. 재시도 전에 프로세스가 종료되면 마지막 영속 상태에 따라 중단 손실이 됩니다.

개발 메뉴에서 수식·미니게임 기록을 함께 JSON으로 내보낼 수 있습니다. ?test 주소의 QA 저장소는 일반 플레이와 분리됩니다. 브라우저 데이터 삭제 시 로컬 기록도 사라집니다.

## 검증

- `node test.cjs`: 수식 규칙 13개 테스트 묶음. 120개 문제 전수 재검증, 20단계+미니게임 건너뛰기 전체 진행.
- `node integration.test.cjs`: 통합 10개 테스트 묶음. 기회 1회, 중단 복구, 최종 단계, 가중 추첨, 두 번째 모듈, 큰 정수, 이전.
- `node ../timer-stop/test.cjs`: 타이머 경계값 등 17개 테스트 묶음.
- http://127.0.0.1:4175/integration-tests.html : 실제 IndexedDB 테스트 5개. 클리어+기회 원자성, 동시 차감, 저장 실패 롤백, 동일 정산 재시도, 20단계 완료.

브라우저에서 기존 2단계 639점 QA 기록 이전, 수식 정산→미니게임 진입, 100점 베팅과 포인터 정지, 결과 새로고침, 3단계 후 새 미니게임을 확인했습니다. 실제 휴대폰에서 ±50ms 체감과 배당 균형은 추가 플레이테스트가 필요합니다.

수식 문제는 20단계, 9/12/16개 타일, 총 120개입니다. 사칙연산·일반 우선순위·정확한 유리수 계산을 사용하며 `node build-cases.cjs`로 재생성합니다. 수식 CONFIG는 engine.js, 타이머 CONFIG는 공유 엔진에 있습니다. 네이티브 앱·서버 순위·현금 결제/환전은 범위 밖입니다.
